# 'Daily review quiz' 예약 작업에 추가할 문구

맥의 Claude 데스크톱 앱 → 예약 작업 **Daily review quiz** → 프롬프트 편집에서 아래처럼 바꿔 주세요.
(또는 맥에 연결된 Cowork 대화에 이 파일 내용을 붙여 넣고 "이대로 Daily review quiz 프롬프트 수정해줘"라고 하면 됩니다.)

---

## 1. 바꿀 줄 (맨 끝 줄)

기존:

```
- 메모리·사이트 데이터베이스는 읽기만 합니다. 사용자 원본 파일은 수정·삭제하지 않습니다. Claude가 쓰는 파일은 오늘의 복습문제 PDF와 _출제기록.json 두 개뿐입니다.
```

새로:

```
- 메모리는 읽기만 합니다. 공부 데스크 데이터베이스에는 오늘의 quiz/daily-YYYY-MM-DD 문서 하나만 쓰고, 그 밖의 사이트 데이터베이스는 읽기만 합니다. 사용자 원본 파일은 수정·삭제하지 않습니다. Claude가 쓰는 파일은 오늘의 복습문제 PDF와 _출제기록.json(사이트 넣기 실패 때만 복습문제_YYYY-MM-DD.json 추가)뿐입니다.
```

## 2. [채점을 안 보낸 날 = 안 푼 날] 섹션 바로 아래에 추가

```
[사이트 채점 결과 읽기 — 사용자 요청, 2026-11-11: 아침 복습문제를 공부 데스크 사이트 '일일 복습' 탭에서 객관식으로 풂]
- 출제 전에 공부 데스크(https://claude.ai/artifact/VjzKRXtTMbpmxwi4nuVqpH)의 데이터베이스 collection "quiz"를 읽습니다. ArtifactData(action "list", 위 url, collection "quiz", query.limit 1000)를 쓰고, 안 되면 claude-artifacts 서버의 db_list(slug "e8c071ae-7f1c-4d69-9668-090243b08776", collection "quiz")를 씁니다. 실패하면 알림 끝에 "사이트 채점 못 읽음".
- 문서 id "daily-YYYY-MM-DD" = 그날 아침 복습. items[].id는 PDF 문항 번호, items[].concept는 개념 이름입니다. res = {문항id: {ok: true/false, g: 찍음 여부, w: 틀린 횟수}}, blankMiss = {B번호: true} = 백지 못 씀.
- res의 u=true는 '모르겠어요'(오답), s=1은 '개념을 보고 풂'입니다. s=1인 문항은 맞혔어도 기억해서 맞힌 것이 아니므로 1·3·7 단계를 진행하지 않고 같은 단계로 다시 냅니다(오답 횟수는 늘리지 않음).
- 그날 문항이 모두 res에 있으면 그날은 채점된 날(graded=true)입니다. ok=false 문항(찍어서 맞힌 것 포함)의 개념과 blankMiss의 B번호 개념이 그날 오답이며, 채팅으로 보낸 오답과 똑같이 1·3·7·마법·백지인출에 반영합니다. 일부만 풀었으면 res가 없는 문항의 개념만 미풀이로 봅니다. 사이트 결과와 채팅 채점이 둘 다 있으면 오답을 합칩니다.
- daily-가 아닌 다른 quiz 문서(오답 재시험 등)에서 ok=false인 문항도 오답 자료로 참고합니다([사이트오답]과 같은 우선순위).
- _출제기록.json의 그날 기록에 "채점: 사이트"와 오답 개념 목록을 적습니다.
```

## 3. [결과물] 섹션 바로 아래에 추가

```
[공부 데스크 '일일 복습'에 넣기 — 사용자 요청, 2026-11-11: "아침 복습문제를 사이트에서 객관식으로 풀고 싶어, 바로 넣어줘"]
- PDF를 만든 뒤 같은 문제(같은 번호·같은 내용)를 공부 데스크 데이터베이스 문서 "quiz/daily-YYYY-MM-DD"(오늘 날짜)에 씁니다. ArtifactData의 쓰기 동작(url "https://claude.ai/artifact/VjzKRXtTMbpmxwi4nuVqpH", collection "quiz", 문서 id "daily-YYYY-MM-DD", 문서 전체를 set)을 쓰고, 안 되면 claude-artifacts 서버의 db_write(slug "e8c071ae-7f1c-4d69-9668-090243b08776", op "set", path "quiz/daily-YYYY-MM-DD")를 씁니다. 그 문서가 이미 있고 res가 비어 있지 않으면(사용자가 풀기 시작함) 덮어쓰지 않습니다.
- 문서 형식(JSON): {"day":"YYYY-MM-DD","title":"아침 복습 M/D","subj":"mix","blank":[{"id":"B1","subj":"생물","t":"개념 이름 + 무엇을 떠올릴지 (PDF 백지인출 쪽과 같음)"}],"items":[{"id":"1","stage":"D+1 또는 D+3·D+7·마법·미풀이·재출제·새 복습","concept":"개념 이름 (_출제기록.json과 같은 이름)","tag":"과목 (생물·한의학·생리학)","src":"출처 짧게","q":"문제","ch":["보기1","보기2","보기3","보기4"],"a":정답 보기 번호(1부터 세는 숫자),"exp":"해설 1~2줄 (확인 필요 표시도 여기)"}],"note":"핵심 3줄 + 비유 한 문장"}
- 모든 문항을 객관식으로 넣습니다: 4지선다는 그대로, OX는 ch ["O","X"], 짝 맞추기는 '올바른 짝 조합 고르기' 4지선다로, 빈칸은 정답 + 헷갈리기 쉬운 오답 3개의 4지선다로. 모든 문항에 ch와 a가 있어야 합니다. 백지인출이 없는 날은 blank를 빈 배열로.
- 쓰기에 실패하면 같은 JSON을 "/Users/sung/Desktop/Claude_결과물/02_일일요약/복습문제/복습문제_YYYY-MM-DD.json"으로 저장하고(사용자가 사이트의 '문제 넣기'에 붙여 넣음), 알림 끝에 "사이트 넣기 실패 — json 저장".
- 알림(PushNotification)에 사이트 넣기 여부도 한 마디 적습니다.
```

## 4. 맨 끝에 추가 (출제기록 정답 한 번 바로잡기)

먼저 저장소의 `복습문제/_출제기록_정답수정목록.json` 파일을 맥의 `Claude_결과물/02_일일요약/복습문제/` 폴더에 넣어 주세요.

```
[출제기록 정답 바로잡기 — 사용자 요청, 2026-11-11: 지난 출제기록 정답 58개가 PDF 정답표와 달라서(보기를 섞은 뒤 기록이 갱신되지 않음) PDF 정답표 기준으로 고침]
- "/Users/sung/Desktop/Claude_결과물/02_일일요약/복습문제/_출제기록_정답수정목록.json"이 있고 _출제기록.json에 "정답수정_적용" 키가 없으면, 목록의 각 항목(날짜·문항번호)에 해당하는 _출제기록.json 기록[날짜].항목의 '정답'을 '바른정답'으로 바꾸고 그 항목에 "정답수정": "PDF 정답표 기준 (원래 기존정답)"을 적습니다. 다 바꾸면 _출제기록.json 맨 위에 "정답수정_적용": "YYYY-MM-DD, n개"를 넣습니다. 한 번만 합니다.
- 옛 개념을 다시 낼 때 정답은 이 바로잡은 값을 기준으로 합니다.
```
